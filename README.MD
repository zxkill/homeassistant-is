# Intersvyaz Doorphone for Home Assistant

Самостоятельная интеграция домофонов провайдера **«Интерсвязь»** для Home Assistant.

Интеграция авторизуется в личном кабинете, получает доступные домофоны, камеры, данные договора и позволяет управлять домофоном стандартными сущностями Home Assistant. Дополнительные внешние сервисы для основной работы не требуются.

> Ветка 2.0 находится в активной модернизации. Перед обновлением рекомендуется сохранить резервную копию каталога `custom_components/intersvyaz`.

## Возможности

- пошаговая авторизация по номеру телефона и коду подтверждения;
- выбор договора/адреса;
- автоматическое обнаружение основного и расшаренных домофонов;
- кнопки открытия двери;
- камеры домофонов;
- баланс договора и профиль абонента;
- автоматическое обновление временных ссылок камеры и открытия;
- локальное распознавание лиц без облачного AI;
- автоматическое открытие двери для известных лиц;
- фоновой анализ выбранных камер;
- события Home Assistant для распознанных и неизвестных посетителей;
- безопасная диагностика без токенов, адресов и биометрических векторов;
- подробное логирование для отладки.

## Установка через HACS

[![Open your Home Assistant instance and open a repository inside the Home Assistant Community Store.](https://my.home-assistant.io/badges/hacs_repository.svg)](https://my.home-assistant.io/redirect/hacs_repository/?owner=zxkill&repository=homeassistant-is&category=integration)

1. Откройте **HACS → Integrations → Custom repositories**.
2. Добавьте репозиторий `https://github.com/zxkill/homeassistant-is` как **Integration**.
3. Установите **Intersvyaz Doorphone**.
4. Перезапустите Home Assistant.
5. Откройте **Настройки → Устройства и службы → Добавить интеграцию → Intersvyaz Doorphone**.

Можно установить вручную: скопируйте каталог `custom_components/intersvyaz` в `/config/custom_components/intersvyaz` и перезапустите Home Assistant.

## Поддерживаемые варианты Home Assistant

Интеграция рассчитана на стандартный механизм Python requirements Home Assistant. Нужные зависимости устанавливаются самим Home Assistant при загрузке интеграции.

### Home Assistant OS / Supervised

Никаких команд `pip`, SSH и ручной установки `dlib` выполнять не нужно. Установите интеграцию через HACS и перезапустите Home Assistant.

### Home Assistant Container

Также не нужно устанавливать библиотеки внутрь Docker-контейнера вручную. Home Assistant загрузит requirements в своё окружение автоматически.

Важно: каталог `/config` должен быть постоянным volume, как и при обычной установке Home Assistant Container.

### Home Assistant Core / venv

Requirements устанавливаются Home Assistant в используемое Python-окружение штатным механизмом платформы.

### Если зависимости распознавания не установились

Версия 2.0 использует готовые бинарные колёса `dlib-bin` и пакет моделей `face-recognition-models`, поэтому компиляция dlib из исходников обычно не требуется.

На редкой или устаревшей архитектуре, для которой нет подходящего wheel, Home Assistant покажет ошибку установки requirement. В таком случае приложите диагностический отчёт и строки журнала с `custom_components.intersvyaz` к issue в репозитории.

## Первичная настройка

1. Введите номер телефона, привязанный к Интерсвязи.
2. Дождитесь звонка/СМС и введите код подтверждения.
3. Если доступно несколько договоров, выберите нужный адрес.
4. Интеграция автоматически получает мобильный токен, список домофонов и CRM-токен.
5. После завершения настройки появятся сенсоры, кнопки и камеры.

Интеграция сама запрашивает основные и расшаренные домофоны и объединяет результаты.

## Сущности

Типовой набор:

- `sensor.*_balance` — баланс договора;
- `sensor.*_profile` — информация профиля;
- `button.*_door_open_*` — открытие конкретного домофона;
- `camera.*_door_camera` — актуальный снимок камеры.

Точные `entity_id` создаёт Home Assistant и они зависят от имени устройства и уже существующих сущностей.

## Камера

Для домофонов с видео создаётся стандартная Camera entity. Снимок запрашивается по временной ссылке, полученной от API Интерсвязи.

В версии 2.0 камера и фоновое распознавание используют **единый Snapshot Manager**. Если Lovelace и фоновый анализ одновременно запрашивают кадр, интеграция повторно использует кратковременный кеш вместо двух одинаковых HTTP-запросов.

Для вывода на панель используйте штатную карточку Camera/Picture Entity.

## Открытие двери

Основной способ — кнопка конкретного домофона.

Также доступен action/service:

```yaml
action: intersvyaz.open_door
data:
  entry_id: "YOUR_CONFIG_ENTRY_ID"
  door_uid: "OPTIONAL_DOOR_UID"
```

Если `door_uid` не указан, используется основной домофон.

## Локальное распознавание лиц

Распознавание выполняется **локально в Home Assistant**. Фотографии посетителей не отправляются в сторонние AI-сервисы.

Версия 2.0 больше не требует ручного `pip install face_recognition` и сборки `dlib`. Home Assistant устанавливает:

- `dlib-bin` — готовый бинарный dlib;
- `face-recognition-models` — модели детектора/дескриптора.

Модели загружаются в память лениво, только когда распознавание действительно используется.

### Добавление лица

Откройте:

**Настройки → Устройства и службы → Intersvyaz Doorphone → Настроить → Добавить лицо**

Укажите имя и загрузите фотографию JPG/PNG.

Требования к фотографии:

- одно хорошо видимое лицо;
- лицо смотрит примерно в камеру;
- без сильного размытия;
- нормальное освещение.

Если на фотографии нет лица или найдено несколько лиц, интеграция откажется сохранять запись и объяснит причину.

### Фоновая обработка

В меню **Настроить → Фоновая обработка камер** выберите домофоны, кадры которых нужно анализировать в фоне.

Если пользователь ещё не выбрал камеры, интеграция использует основной видеодомофон как значение по умолчанию.

### Автооткрытие

Для сохранения обратной совместимости 2.0-beta повторяет текущее поведение: при уверенном совпадении известного лица выполняется callback открытия двери. Повторное открытие одного домофона блокируется cooldown-интервалом.

Перед публичным стабильным релизом 2.0 планируется отдельная UI-настройка режима `только распознавать / распознавать и открывать`.

## События Home Assistant

Версия 2.0 публикует события, поэтому для Telegram, уведомлений и других сценариев больше не нужно изменять `face_manager.py` вручную.

### Известное лицо

Событие:

```text
intersvyaz_face_recognized
```

Данные события:

```yaml
door_uid: "..."
person: "Алексей"
distance: 0.41
threshold: 0.6
faces_detected: 1
```

### Неизвестный посетитель

Событие:

```text
intersvyaz_unknown_person
```

Данные:

```yaml
door_uid: "..."
distance: 0.74
threshold: 0.6
faces_detected: 1
```

Одинаковые события ограничиваются коротким cooldown, чтобы человек перед камерой не создавал событие каждые две секунды.

### Пример автоматизации уведомления

```yaml
alias: "Домофон: распознано лицо"
mode: queued
triggers:
  - trigger: event
    event_type: intersvyaz_face_recognized
actions:
  - action: persistent_notification.create
    data:
      title: "Домофон"
      message: "Распознано лицо: {{ trigger.event.data.person }}"
```

При необходимости в автоматизации можно отдельно вызвать `camera.snapshot` и отправить кадр через любую настроенную систему уведомлений Home Assistant.

## Диагностика

Откройте:

**Настройки → Устройства и службы → Intersvyaz Doorphone → три точки → Скачать диагностику**

Диагностика специально не содержит:

- токены;
- номер телефона;
- адрес проживания;
- MAC домофона;
- временные ссылки открытия/снимков;
- биометрические векторы известных лиц.

В отчёте остаётся техническая информация: число домофонов, наличие камер, число известных лиц и доступность локального recognition engine.

## Логирование

Основные logger names:

```text
custom_components.intersvyaz
intersvyaz.face_manager
intersvyaz.recognition
intersvyaz.snapshot
intersvyaz.background
intersvyaz.camera
intersvyaz.events
```

Для подробной диагностики временно добавьте в `configuration.yaml`:

```yaml
logger:
  default: info
  logs:
    custom_components.intersvyaz: debug
    intersvyaz.face_manager: debug
    intersvyaz.recognition: debug
    intersvyaz.snapshot: debug
    intersvyaz.background: debug
    intersvyaz.camera: debug
    intersvyaz.events: debug
```

После диагностики рекомендуется вернуть уровень `info`, чтобы не засорять журнал.

## Обновление поверх 1.x

Для тестирования beta-версии можно скопировать изменённые файлы поверх существующего `custom_components/intersvyaz`, затем полностью перезапустить Home Assistant.

Перед заменой файлов сделайте резервную копию текущего каталога интеграции.

Сохранённые лица остаются в `ConfigEntry.options` в совместимом формате `name + 128-мерный descriptor`, поэтому повторная регистрация лиц обычно не требуется.

## Разработка

Ключевой принцип 2.0: интеграция является самостоятельным источником сущностей, событий и действий Home Assistant и не зависит от каких-либо внешних домашних ассистентов или пользовательских проектов.

Основные слои:

```text
Intersvyaz Cloud API
        ↓
API client / coordinator
        ↓
Door runtime data
   ├── buttons
   ├── cameras
   ├── sensors
   ├── snapshot manager
   └── face recognition
        ↓
Home Assistant entities / actions / events
```

Тесты запускаются из корня репозитория:

```bash
pytest
```

## Сообщить об ошибке

При создании issue приложите:

1. версию Home Assistant;
2. способ установки: OS / Container / Core;
3. архитектуру: x86_64 / aarch64 / другое;
4. диагностический файл интеграции;
5. релевантный фрагмент журнала.

Не публикуйте токены, полный номер телефона и временные URL открытия двери.
