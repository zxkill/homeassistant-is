# Intersvyaz Doorphone for Home Assistant

[![Open your Home Assistant instance and open a repository inside the Home Assistant Community Store.](https://my.home-assistant.io/badges/hacs_repository.svg)](https://my.home-assistant.io/redirect/hacs_repository/?owner=zxkill&repository=homeassistant-is&category=integration)

Интеграция **«Интерсвязь»** для Home Assistant.

Позволяет подключить домофоны и камеры «Интерсвязи» к Home Assistant, открывать двери, просматривать камеры, использовать события в автоматизациях и при необходимости включить локальное распознавание лиц.

> Интеграция не является официальным продуктом АО «Интерсвязь».

## Возможности

- авторизация по номеру телефона и коду подтверждения;
- поддержка нескольких договоров и адресов;
- автоматическое обнаружение доступных домофонов;
- отдельное устройство Home Assistant для каждого домофона;
- открытие двери из Home Assistant;
- просмотр камер домофона и камер «Умного двора»;
- live-видео через стандартные возможности Camera Home Assistant;
- поддержка HLS и low-latency потока при наличии совместимого WebRTC/go2rtc;
- автоматическое обновление временных ссылок на камеры;
- отображение баланса и данных договора;
- локальное распознавание лиц;
- привязка распознанных лиц к `person.*` Home Assistant;
- режим наблюдения без автоматического открытия;
- автоматическое открытие двери по подтверждённому распознаванию;
- выбор камер для фонового анализа;
- события распознавания, неизвестного посетителя и открытия двери;
- сенсор последнего посетителя;
- повторная авторизация без удаления интеграции;
- встроенная диагностика с маскированием персональных данных и токенов.

## Требования

- Home Assistant **2026.8.0 или новее**;
- действующий аккаунт «Интерсвязи»;
- доступ Home Assistant в интернет;
- доступ к сервисам `api.is74.ru`, `td-crm.is74.ru` и `cams.is74.ru`.

Все Python-зависимости устанавливаются Home Assistant автоматически. Вручную выполнять `pip install` не требуется.

## Установка

### Через HACS

1. Нажмите кнопку **HACS** в начале README.

   Или добавьте репозиторий вручную:

   ```text
   https://github.com/zxkill/homeassistant-is
   ```

   в **HACS → Custom repositories**, тип — **Integration**.

2. Установите **Intersvyaz Doorphone**.
3. Перезапустите Home Assistant.
4. Откройте **Настройки → Устройства и службы → Добавить интеграцию**.
5. Найдите **Intersvyaz Doorphone**.

### Ручная установка

Скопируйте каталог:

```text
custom_components/intersvyaz
```

в:

```text
/config/custom_components/intersvyaz
```

После этого перезапустите Home Assistant.

## Подключение аккаунта

При добавлении интеграции потребуется:

1. указать номер телефона;
2. ввести код подтверждения от «Интерсвязи»;
3. выбрать договор или адрес, если их несколько.

После успешной авторизации интеграция автоматически загрузит доступные домофоны и камеры.

Пример структуры устройств:

```text
Интерсвязь
├── Баланс
├── Профиль
│
├── Домофон — адрес / подъезд
│   ├── Открыть дверь
│   ├── Камера
│   ├── Состояние
│   ├── Последний посетитель
│   └── Событие
│
└── Камеры двора
    ├── Камера подъезда
    ├── Камера двора
    └── ...
```

## Открытие двери

Для каждого доступного домофона создаётся кнопка **«Открыть дверь»**.

Дверь также можно открыть из автоматизации:

```yaml
action: intersvyaz.open_door
data:
  entry_id: YOUR_CONFIG_ENTRY_ID
```

Если в аккаунте несколько домофонов, можно указать конкретный `door_uid`.

## Камеры

Интеграция создаёт стандартные `camera`-сущности Home Assistant для доступных камер.

Поддерживаются:

- камера домофона;
- камеры подъездов;
- камеры «Умного двора», доступные аккаунту;
- статические снимки;
- живой видеопоток.

Камера основного подъезда связывается с устройством соответствующего домофона. Остальные доступные камеры создаются как отдельные устройства.

### Live-видео

Основной совместимый режим просмотра — **HLS**.

Если активный WebRTC/go2rtc поддерживает realtime-источник камеры, интеграция может автоматически использовать MSE/Realtime WebSocket с меньшей задержкой.

Если realtime-источник недоступен, камера автоматически работает через HLS.

Дополнительные `Generic Camera` для обычной работы интеграции создавать не требуется.

### Пример карточки камеры

```yaml
type: picture-entity
entity: camera.YOUR_CAMERA
camera_image: camera.YOUR_CAMERA
camera_view: live
show_name: true
show_state: false
```

## Распознавание лиц

Распознавание выполняется локально в Home Assistant. Изображения не отправляются во внешний сервис распознавания.

Настройки находятся здесь:

**Настройки → Устройства и службы → Intersvyaz Doorphone → Настроить**

Доступны:

- **Распознавание и автооткрытие**;
- **Добавить лицо**;
- **Связать лицо с человеком Home Assistant**;
- **Удалить лицо**;
- **Камеры фонового анализа**.

### Добавление лица

1. Создайте человека в **Настройки → Люди**, если его ещё нет.
2. Откройте настройки интеграции.
3. Выберите **Добавить лицо**.
4. Выберите нужного человека.
5. Загрузите фотографию.

Для регистрации лучше использовать фотографию:

- с одним человеком;
- с хорошо видимым лицом;
- без сильного поворота головы;
- с нормальным освещением;
- без сильного размытия.

Для одного человека может храниться несколько шаблонов лица.

### Движок распознавания

На совместимом процессоре используется локальный нейросетевой движок на базе dlib ResNet.

Если нативный движок несовместим с процессором или окружением Home Assistant, интеграция переключается на переносимый резервный локальный движок. Остальные функции интеграции продолжают работать независимо от распознавания лиц.

### Режимы

**Выключено** — изображения не анализируются.

**Только распознавать** — интеграция определяет известных посетителей, обновляет сенсоры и публикует события, но не открывает дверь автоматически.

**Распознавать и автоматически открывать** — после подтверждённого совпадения интеграция может открыть дверь соответствующего домофона.

Для автооткрытия используются несколько последовательных совпадений, порог распознавания и задержка между повторными открытиями.

> Автоматическое распознавание лица по изображению не является полноценной системой контроля доступа и не выполняет liveness/anti-spoof проверку. Используйте автооткрытие только после самостоятельной оценки риска.

## Камеры фонового анализа

В настройках интеграции можно выбрать камеры, изображения с которых будут использоваться для фонового распознавания.

Для камер, не связанных с доступным домофоном, распознавание можно использовать в событиях и автоматизациях, но автоматическое открытие двери для них недоступно.

## Последний посетитель

Для домофонов создаётся сенсор последнего посетителя.

В зависимости от результата распознавания он может содержать имя известного человека или информацию о неизвестном посетителе.

## События

Для домофона доступна `EventEntity` со следующими типами событий:

- `face_recognized`;
- `unknown_person`;
- `door_opened`;
- `door_open_failed`.

Также события публикуются в event bus Home Assistant:

- `intersvyaz_face_recognized`;
- `intersvyaz_unknown_person`;
- `intersvyaz_door_opened`;
- `intersvyaz_door_open_failed`.

### Пример уведомления о знакомом посетителе

```yaml
alias: Домофон — знакомый посетитель
triggers:
  - trigger: event
    event_type: intersvyaz_face_recognized

conditions:
  - condition: template
    value_template: "{{ trigger.event.data.confirmed | default(false) }}"

actions:
  - action: persistent_notification.create
    data:
      title: Интерсвязь
      message: >-
        Распознано лицо: {{ trigger.event.data.person }}
```

Событие распознавания может содержать:

- `entry_id`;
- `door_uid`;
- `door_name`;
- `person`;
- `person_entity_id`;
- `distance`;
- `match_score`;
- `faces_detected`;
- `streak`;
- `required_matches`;
- `confirmed`;
- используемый движок распознавания.

## Actions

### `intersvyaz.open_door`

Открывает основной или указанный домофон.

### `intersvyaz.add_known_face`

Добавляет известное лицо программно. Изображение можно передать через `image_url` или `image_base64`. Лицо можно связать с существующей сущностью `person.*`.

### `intersvyaz.remove_known_face`

Удаляет известное лицо.

Для обычного использования удобнее управлять лицами через настройки интеграции.

## Повторная авторизация

Если авторизация «Интерсвязи» перестала действовать, Home Assistant покажет уведомление **«Требуется повторная авторизация»**.

Пройдите авторизацию повторно через интерфейс Home Assistant. Удалять и заново добавлять интеграцию не требуется.

## Перенастройка

Через интерфейс Home Assistant можно повторно пройти авторизацию и выбрать договор без удаления существующей интеграции.

## Диагностика

Диагностический отчёт можно скачать через:

**Настройки → Устройства и службы → Intersvyaz Doorphone → ⋮ → Скачать диагностику**

Диагностика содержит техническое состояние интеграции, но не должна содержать открытые:

- токены авторизации;
- номер телефона;
- device ID;
- MAC-адреса;
- домашние адреса;
- временные подписанные URL камер;
- биометрические шаблоны лиц.

Диагностику можно прикладывать к Issue при сообщении о проблеме.

## Подробное логирование

Для диагностики можно временно включить debug-логирование:

```yaml
logger:
  logs:
    custom_components.intersvyaz: debug
```

После изменения `configuration.yaml` перезапустите Home Assistant.

Для проблем с видеопотоком полезны сообщения:

```text
[YARD_STREAM]
[YARD_HLS_COMPAT]
[CAMERA][STREAM_SOURCE]
```

Для распознавания лиц:

```text
[FACE]
```

Debug-логирование может создавать большое количество записей, поэтому после диагностики рекомендуется вернуть обычный уровень логирования.

## Устранение проблем

### Интеграция просит войти повторно

Откройте уведомление Home Assistant и завершите повторную авторизацию.

### Не открывается дверь

Проверьте:

- доступен ли домофон в приложении «Интерсвязь»;
- не требуется ли повторная авторизация;
- относится ли используемая кнопка к нужному домофону.

### Камера не показывает изображение

Проверьте доступность камеры в приложении «Интерсвязь».

Затем перезагрузите интеграцию и посмотрите журнал:

```text
custom_components.intersvyaz.camera
custom_components.intersvyaz.yard_stream
custom_components.intersvyaz.yard_hls_compat
```

### Live-видео работает с большой задержкой

Обычный HLS имеет естественную задержку.

Low-latency режим доступен, если активный WebRTC/go2rtc поддерживает realtime-источник камеры.

В debug-журнале:

```text
[CAMERA][STREAM_SOURCE] ... selected=realtime_flussonic
```

означает использование realtime-потока.

```text
[CAMERA][STREAM_SOURCE] ... selected=hls
```

означает использование HLS.

### Не добавляется лицо

Проверьте, что на фотографии ровно одно хорошо видимое лицо, достаточное освещение и нет сильного размытия.

Дополнительную информацию можно найти в журнале по сообщениям `[FACE]`.

### Распознавание недоступно

Проверьте журнал интеграции. Если основной нативный движок несовместим с текущим CPU, интеграция может использовать резервный локальный движок.

## Обновление

При установке через HACS:

1. откройте HACS;
2. выберите **Intersvyaz Doorphone**;
3. установите доступное обновление;
4. перезапустите Home Assistant.

Перед крупными обновлениями Home Assistant и пользовательских интеграций рекомендуется иметь актуальную резервную копию.

## Безопасность и приватность

Интеграция работает с данными аккаунта «Интерсвязи», изображениями камер и при включённом распознавании — с биометрическими шаблонами лиц.

Не публикуйте:

- содержимое `.storage/core.config_entries`;
- необработанные ответы API;
- токены авторизации;
- временные URL камер;
- персональные данные из журналов.

Шаблоны известных лиц хранятся локально в конфигурации Home Assistant и могут попадать в резервные копии Home Assistant.

При публикации отчёта об ошибке используйте встроенную **Диагностику** и предварительно проверьте приложенный журнал на наличие персональных данных.
